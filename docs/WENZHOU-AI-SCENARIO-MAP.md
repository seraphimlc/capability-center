# 温州项目 AI：场景 / 能力 / 功能地图

分支：`feature/wenzhou-ai-workbench`
定位：**能力中心是 AI 能力底座，温州项目是长在上面的业务层。** 不另起一套账号、目录、计费或模型网关。

---

## 0. 先统一几个词

| 词 | 含义 | 在能力中心里的落点 |
|---|---|---|
| 能力 / Capability | 一个可调用的工具：输入 schema、输出、价格、调用记录 | `tools` + `InvokeService` |
| 专家 / Expert | 有角色提示词、可用能力、知识库、模型和输出契约的作业单元 | `agents` 扩展为任务型专家 |
| 场景 / Scenario | 一个有名字的多步作业：输入、步骤、数据依赖、输出模板、验收 | 新增 `scenarios` + `scenario_runs` |
| 任务 / Task | 一次场景运行：输入、状态、产物、耗时、积分、审计 | 复用 BullMQ + 新增任务中心 |
| AI 应用 / App | 有持久数据的业务界面：商品库、CRM、营销素材、店铺中心 | 新增 app 模块 |
| 技能 / Skill | 可被专家调用的能力包，可安装/启停/配权限 | 现有目录 + Skill 市场扩展 |

**原则：能力只做一次，专家和场景只做编排。** 不允许在场景里再写一套上游调用、计费或鉴权。

### 0.1 前台文案 vs 模型层

本期可以跟温州项目的叫法，但**只换前台文案，不动模型层**：

| 前台文案（温州叫法） | 模型 / 表 / API | 说明 |
|---|---|---|
| 专家 | `Agent` | 只是显示叫“专家”，不新增 `expert` 实体 |
| 场景 | `Scenario` | 只是显示叫“场景”，不改表名/字段 |
| 任务 | `Run` | 用户看到“任务”，底层是运行实例 |
| 能力 | `Tool` / Capability | 现有能力目录 |
| 应用 | App（温州业务层） | 商品库/CRM/营销中心，不进核心模型 |
| 数据源 | `DataSource` | |
| 知识库 | `KnowledgeBase` | |
| 企业 | `Enterprise` | |
| 积分/套餐 | `CreditAccount` / `Plan` | |

规则：

- 不因为温州叫法改表名、字段名、API 路径。
- 不新增“专家”“场景”专用实体；它们只是 `Agent` / `Scenario` 的展示文案。
- 文案集中在一处（后续 `apps/www/src/lib/labels.ts`），换客户只换文案。
- 温州 UI 可以叫“专家中心/场景/任务”，代码里仍是 Agent/Scenario/Run。

## 1. 场景总览

报价表 AI 工作台包含：

- **8 类专家**：总控、商品、获客、合规、数据洞察、行研、营销、其他定制。
- **21 个场景工作流**：选品、商品内容、视觉、获客、营销、分析、报价等。
- **4 个 AI 应用**：AI 商品库、智慧 CRM、全球店铺中心、智能营销中心。
- **8 项平台能力**：模型配置、模型审计、智能体管理、知识库、任务中心、自动化、Skill 市场/MCP、套餐订阅。
- **6 个平台的嵌入式 AI**：门户、B2B 商城、服务市场、外综服、SCM、数据中台。

### 1.2 场景组合：9 个工作流 + 21 个配置

21 个场景不做 21 套流程。按“同一种作业模式”合并成 **9 个通用工作流**，温州前台仍然保留 21 个场景入口，每个入口是一份配置（输入表单、提示词、输出模板、启用的能力）。

| # | 工作流 | 覆盖温州场景 | 配置/模式 | 优先级 | 依赖 |
|---|---|---|---|---|---|
| 1 | 选品与市场分析 | 1 选品、11 行研、20 爆款、21 品类/市场机会 | 选品决策 / 行业报告 / 爆款预测 / 品类机会 | **P0** | LinkFox 市场/热销；无 Pending |
| 2 | 竞品洞察 | 6 竞品 | 单竞品 / 多竞品对比 | **P0** | LinkFox 竞品/评论；店铺可选 |
| 3 | 合规初筛 | 4 合规 | 文字/图片/商标/专利 | **P0** | 合规工具 + 商标；商标额度 |
| 4 | 商品内容生产 | 2 商品描述、8 智能打标 | 标题/五点/详情/翻译/打标 | P1（Phase 2） | LinkFox 文本/多模态；商品库（新建） |
| 5 | 视觉素材生产 | 3 商品图/场景图 | 白底/场景/套图/视频 | P1（Phase 2） | LinkFox AIGC；素材库（新建） |
| 6 | 客户洞察与获客 | 12 海关、13 采购商、14 画像、17 相似客户 | 海关清单 / 采购商 / 画像 / 相似扩量 | P1（Phase 3） | 格兰德 Pending；CRM |
| 7 | 询盘报价与触达 | 5 需求解析、15 邮件、18 定价、19 报价单 | 解析 → 定价 → 报价 → 邮件 | P1（Phase 3） | 阿里云邮件 Pending；报价单应用 |
| 8 | 经营诊断 | 7 经营诊断 | 店铺/广告/Listing/流量诊断 | P1（Phase 2） | 真实店铺授权；LinkFox 店铺工具 |
| 9 | 营销内容与社媒 | 9 营销内容、10 社媒、16 评论互动 | 广告/邮件/社媒/评论回复 | P2 | LinkFox AIGC；渠道发布后置 |

覆盖检查：4+1+1+2+1+4+4+1+3 = **21 个场景全覆盖**。

**合并后的规则：**

- 工作流是运行时（步骤、数据、计费、审计）；配置是温州入口（表单、提示词、模板、能力选择）。
- 新增一个场景 = 新增一份配置，不新增一套流程；只有出现全新作业模式时才新增工作流。
- 行研报告保留独立入口，但共用工作流 1；报价单是工作流 7 的最后一步，PDF/审批单独做能力；相似客户并入工作流 6，不单独做；评论互动并入工作流 9，先不做发布。
- 动态定价先做规则版，并入工作流 7；真正的动态模型往后放。

**优先级：**

- **P0（第一批）**：1 选品、2 竞品、3 合规初筛。
- **P1**：4 商品内容、5 视觉素材、8 经营诊断（Phase 2）；6 客户洞察、7 询盘报价（Phase 3，等数据/邮件）。
- **P2**：9 营销内容与社媒，以及各工作流的深度模式。

---## 3. 8 类专家

| 专家 | 职责 | 主要调用 | 现有基础 | 需要补 |
|---|---|---|---|---|
| 总控专家 | 理解需求、推荐专家、引导发起任务 | 全部专家 | 会话、助手 | 意图路由、专家推荐、任务编排 |
| 商品专家 | 商品采集/分析、标题卖点、多语言描述、商品图 | 场景 2、3、8 | 12 个助手、Listing 工具 | 商品库、生图、任务型输出 |
| 获客专家 | 海关/采购商数据、市场筛选、潜客、触达 | 场景 12–15 | 工具目录、CRM（新增） | 数据连接器、画像、邮件 |
| 合规专家 | 准入、关税、认证、知识产权、外汇税务、单证风险 | 场景 4 + 商标 | `compliance-check`、商标 3 能力 | 合规知识库、规则库 |
| 数据洞察专家 | 商品/店铺/客户/询盘/订单指标、异常、趋势 | 场景 7 | 店铺、调用记录 | 数据接入、指标模型 |
| 行研专家 | 行业/市场/政策/海关/社媒/竞品研究 | 场景 11 | 无 | 数据接入、报告生成 |
| 营销推广专家 | 多语言营销内容、投放建议 | 场景 9、10 | 文案/翻译工具 | 生图/视频、素材库 |
| 其他定制专家 | 按项目配置专属专家 | 任意 | 助手配置 | 专家配置 UI、资源组合 |

**专家不是新的一堆 prompt 文件。** 专家 = 现有 agent + 任务型输入/输出契约 + 可用能力/知识库/模型 + 权限。能复用 `agents`、`agent_tools`、`ai_models` 就不要新建表。

## 5. 8 项平台能力

| 能力 | 报价表要求 | 现有 | 整合方式 |
|---|---|---|---|
| 模型配置 | 文本/生图/视频模型，供应商、上下文、限额、测试、启停、默认 | `ai_models`、`ModelService` | 加 `modality`，扩图片/视频适配，不新建模型表 |

## 6. 嵌入式 AI（第二阶段以后）

| 平台 | 嵌入式 AI | 整合方式 |
|---|---|---|
| 平台门户 | 智能客服 IM、智能入驻引导 | 复用会话 + 新增 IM/入驻知识库 |
| B2B 商城 | 智能搜索、AI 询价、商品提效、采集、信用证/报关单识别 | 调用能力中心工具 + 商城业务对象 |
| 服务市场 | AI 助手、服务商推荐、物流报价 | 场景 + 服务商数据 |
| 外综服 | 合规 Agent、境内/境外知识库、合规诊断 | 合规专家 + 知识库 |
| 供应链 SCM | 供应商评级、订单分发、履约预警、补货、智能入库 | 场景 + SCM 数据 |

这些不要在能力中心里重写业务系统；用 API/事件把 AI 能力嵌进去。

## 8. 第一批 vertical slice

第一批只做 3 个场景：**选品、竞品、合规初筛**。它们不依赖格兰德数据、阿里云邮件和知识库，能先把“专家 → 场景 → 任务 → 企业计费 → 审计 → 产物”跑通。

具体输入、步骤、报告结构、验收样例见 [P0 三个工作流的配置草案](WENZHOU-AI-P0-CONFIGS.md)。

### 8.1 选品决策（P0）

流程：

```
输入：关键词、站点、成本/售价、类目
  ↓
选品简报（product-picker）
  ↓
竞品洞察（competitor-insight，可选）
  ↓
利润测算（profit-estimator）
  ↓
季节日历（season-calendar）
  ↓
合规初筛（compliance-check，可选）
  ↓
输出：选品报告 + 调用记录 + 积分流水
```

- 新增：`scenarios`（选品）、`scenario_runs`、任务页、报告模板。
- 复用：4–5 个现有工具、`InvokeService`、`BillingService`、`AgentService`、审计。
- 验收：一次任务能看到步骤、每步调用、总积分、报告、失败释放；不新增任何上游直连代码。

### 8.2 竞品洞察（P0）

流程：

```
输入：关键词/ASIN/竞品标题、站点、数量、店铺（可选）
  ↓
竞品关键词洞察（competitor-insight）
  ↓
选品数据竞品查询（lf-sellersprite-competitor-lookup，可选）
  ↓
亚马逊评论（lf-amazon-reviews-list，可选）
  ↓
监控竞品动态（lf-expert-amazon-competitor-monitor，需绑店，可选）
  ↓
输出：竞品报告
```

- 无店铺时跳过绑店步骤，不阻断整次运行。
- 先做单次洞察，不做定时监控；定时归自动化阶段。

### 8.3 合规初筛（P0）

流程：

```
输入：商品名、类目、目标国家、Listing 文案/图片、商标名（可选）
  ↓
Listing 合规检查（compliance-check）
  ↓
近似商标检索（trademark-similar-search，可选）
  ↓
尼斯分类（trademark-nice-class，可选）
  ↓
输出：合规报告 + 免责声明
```

- 商标当前额度不足，作为可选步骤；失败标记 skipped，不阻断基础合规初筛。
- 合规知识库/RAG 不在第一批，先用工具 + 模型 + 固定规则。

### 8.4 商品专家（P1，不在第一批）

- 复用：`listing-copy`、`title-optimizer`、`translate-listing`、`main-image-brief`、LinkFox 生图/套图。
- 新增：AI 商品库、素材库、生图异步任务。

## 10. 已定决策

| 主题 | 决定 |
|---|---|
| 品牌 / 多语言 | 品牌先叫「能力中心」；不做多语言 |
| 模型 | 文本走 xytoken；图片/视频先用 LinkFox AIGC 能力 |
| 助手 → 专家 | 先改用户端/管理端文案和导航，数据库与 API 继续用 `agents` |
| 租户模型 | 单平台多企业；企业—员工两层；企业管理员管人、管额度、看账单 |
| 积分 | 企业积分账户 + 员工子额度；对外按任务/场景一次，内部按工具/模型记账 |
| 套餐 | 平台代开、线下收款；按月过期、不结转、无缓冲 |
| 数据 | 先新建数据；现有商品/CRM/店铺/订单系统后面再接 |
| 外部能力 | 优先 LinkFox、创知汇等现有能力；自建放后面 |
| Pending 数据 | 海关/采购商用格兰德数据；邮件用阿里云邮件服务；相似客户 Pending |
| 场景组合 | 21 个场景压成 9 个工作流 + 21 份配置；P0 3 个、P1 5 个、P2 1 个 |
| 第一批 | 选品、竞品、合规初筛 |
| 管理端 | 能力和专家工作台优先，场景工作台随后；发布流程草稿 → 试跑 → 发布 |
| 知识库 | 先做合规、商品、客服三个库；业务提供内容 |
| AI 应用 | AI 商品库、CRM 先新建轻量版；营销中心先做素材库 |
| 成功标准 | 先试点，不直接按验收做 |
| 时间 | 不设上线日期，做完为准 |
| 交付 | 内部复用，不单独交付平台源码 |
